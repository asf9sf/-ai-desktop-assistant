# 音乐播放模块设计文档

> 多平台音乐搜索与本地播放，VIP 歌曲自动识别并回退到 B 站搜索完整版。支持网易云音乐搜索、音频下载缓存、歌单管理、播放控制。

---

## 1. 设计理念

**一个统一入口，多平台后端**：用户只需自然语言点歌（"播放离人"），智能体通过音乐播放器自动调度可用的音乐平台（当前支持网易云），完成搜索 → 获取链接 → 下载缓存 → 本地播放全流程。

**试听片段自动回退**：当网易云返回 VIP 歌曲的试听片段（≤60 秒）时，系统不会播放该片段，而是自动在 B 站搜索"歌名 + 歌手（最多收藏排序）"，并点击第一个视频，为用户找到完整版。

**离线优先 + 浏览器兜底**：能离线下载播放的尽量离线，遇到版权/VIP 限制时用浏览器作为兜底方案。

## 3. 核心架构

### 3.1 调用链路

```
用户: "播放离人"
  ↓
agent_core._fast_intent 正则匹配 "播放" 意图
  ↓
agent_core._execute_tool("play_music", "离人")
  ↓
music_player.play_by_name("离人")
  ├── ncm.fetch_songs("离人")       # 网易云搜索
  ├── ncm.fetch_song_audio(song)    # 获取播放链接（br=320000 高码率）
  ├── music_player.play(song)
  │     ├── 下载音频（带 Content-Length 校验 + 进度日志）
  │     ├── 校验 MP3 完整性（_verify_mp3）
  │     ├── 试听检测（_looks_like_preview：时长 ≤ 60 秒）
  │     ├── 试听 → 跳过播放，返回 preview=True
  │     └── 非试听 → os.startfile 系统播放器
  └── 返回 (ok, msg, info={preview, song_name, artist})
  ↓
agent_core 检测 preview=True
  ↓
agent_core._fallback_bilibili_search("离人", "林志炫")
  ├── browser.bilibili_search("离人 林志炫", order="stow")
  │   → 打开 https://search.bilibili.com/all?keyword=...&order=stow
  ├── time.sleep(1.5) 等待页面加载
  └── browser.find_and_click_first_result()
        → 点击第一个视频，用户在浏览器中观看
```

### 3.2 文件结构

**song.id.mp3** 缓存路径：`data/cache/music/{song.id}.mp3`

**歌单持久化**：`data/playlist.json`（歌曲 ID 去重）

## 4. 网易云音乐平台 (ncm.py)

### 4.1 第三方 API

使用第三方 NodeJS 网易云 API（默认 `http://45.152.64.114:3005`，支持多节点自动切换）。

| 端点 | 用途 |
|------|------|
| `/search?keywords=xxx&limit=1` | 歌曲搜索 |
| `/song/url?id=xxx&br=320000` | 获取 320kbps 播放链接 |
| `/lyric?id=xxx` | 歌词查询 |

### 4.2 关键设计

- **多节点自动切换**：预置多个 API 节点，启动时和请求失败时自动探测可用节点
- **高码率请求**：`/song/url` 传 `br=320000`（320kbps），避免默认返回低音质
- **版权识别**：当 `br_data[0].url` 为空时，日志标记为"版权限制"

## 5. 音频完整性校验

### 5.1 下载阶段（_download_audio）

- 使用 `stream=True` 分块下载，`chunk_size=65536`
- 每 512KB 输出进度日志
- 对比 `Content-Length` 与实际下载量：下载量 < 50% 视为不完整
- 空下载（0 字节）直接判失败
- 超时配置：`timeout=(10, 120)`（连接 10s，读取 120s）

### 5.2 下载后校验

```python
if file_size < 10_000:              # 异常过小
    拒绝

if song.duration > 0:
    est_bitrate = file_size * 8 / duration   # 估算码率
    if est_bitrate < 64 kbps:
        告警（可能片段/低音质）

    if _looks_like_preview(size, duration):  # 时长 ≤ 60 秒
        info["preview"] = True              # 标记为试听

_verify_mp3(path)                   # 检查 MP3 头 + 文件尾
```

### 5.3 _verify_mp3 校验

- 检查 MP3 头：`ID3` 标签 或 `0xFF 0xE0` MPEG 同步字
- 检查文件尾部 256 字节：截断的文件尾部通常异常
- 文件 < 1024 字节直接判为损坏

### 5.4 _looks_like_preview 判断规则

- 时长 ≤ 60 秒 → 试听片段
- 时长未知时，文件 < 500KB → 疑似试听

## 6. 试听回退机制

### 6.1 为什么不播放试听

网易云公共节点对 VIP 歌曲只返回 45 秒左右的试听片段。播放这类片段：
- 用户体验差（听一半就没了）
- 误导用户以为系统故障
- 浪费缓存空间

### 6.2 回退策略

1. `music_player.play()` 检测到试听 → **直接返回，不启动播放器**
2. `agent_core` 拿到 `preview=True` → 停止可能的残留播放
3. 调用 `_fallback_bilibili_search(song_name, artist)`
4. 在 B 站搜索"歌名 + 歌手"，按**最多收藏**排序（`order=stow`）
5. 点击第一个视频，用户在浏览器中观看完整版

### 6.3 B 站搜索 URL

```
https://search.bilibili.com/all?keyword=离人 林志炫&order=stow
```

- `keyword`：歌名 + 歌手名（精准匹配）
- `order=stow`：最多收藏排序（确保搜索结果是高质量/高人气版本）

### 6.4 独立参数

`browser.bilibili_search(keyword, order="stow")` 的 `order` 参数仅在音乐回退场景使用，其他场景（如用户主动搜索）不受影响。

## 8. 播放控制

| 意图 | 触发词 | 行为 |
|------|--------|------|
| 播放 | "播放XX"、"点歌XX"、"来首XX" | 搜索并播放 |
| 列表 | "音乐列表"、"我的歌单"、"多少首歌" | 显示歌单 |
| 下一首 | "换一首"、"下一首"、"下一个" | 停止当前，切换到下一首 |
| 上一首 | "上一首"、"上一个" | 切换到上一首 |
| 暂停 | "暂停"、"停" | 暂停播放 |
| 恢复 | "继续"、"播放" | 恢复播放 |
| 停止 | "停止播放"、"关掉音乐" | 完全停止 |

### 8.1 播放实现

使用 `os.startfile(path)` 调用系统默认播放器：
- 无额外音频依赖（无需 pygame/pyaudio）
- 利用系统原生播放能力，跨线程安全
- 支持 Windows 媒体快捷键暂停/继续

### 8.2 音乐快速路径

在 `agent_core._fast_intent` 中，音乐意图（`play_music`、`music_control`、`list_music`、`music_lyrics`）使用**正则快速匹配**，绕过 LLM 推理，直接调用对应工具，响应延迟 < 100ms。

## 9. 关键设计决策

### 9.1 三元素返回值

`play() / play_by_name() / play_next() / play_prev()` 返回 `(bool, str, dict)`：
- `bool`：是否成功
- `str`：消息文本
- `dict`：元信息 `{preview, song_name, artist}`

这使得上层（agent_core）能根据 `preview` 标记决定是否回退 B 站，而不是靠字符串匹配。

### 9.2 试听检测而非歌曲黑名单

不同歌曲在不同节点的版权状态不同。不维护"VIP 歌曲黑名单"，而是根据**实际下载结果**判断：
- 时长 ≤ 60 秒 → 试听
- 这比硬编码歌曲列表更准确、更可维护

### 9.3 系统播放器优先

放弃 `pygame` / `pyaudio` / `winsound`：
- 这些库需要 GPU 或有线程亲和性问题
- `os.startfile` 利用系统原生播放器，零依赖、跨线程安全
- 用户可以用媒体快捷键或系统音量自由控制

### 9.4 缓存复用 + 自动失效

已缓存的 MP3 文件：
- 通过 `_verify_mp3` 校验完整性
- 通过 `_looks_like_preview` 检查是否为试听片段
- 试听缓存自动删除并重新下载
- 损坏缓存自动删除并重新下载

### 9.5 B 站搜索用最多收藏排序

`order=stow` 确保第一个搜索结果是收藏数最多的视频，通常也是最完整、最高质量的版本。避免按综合排序出现低质量/翻唱/片段排在前面的问题。

## 11. 已知限制

1. **仅支持网易云**：当前只实现了网易云平台，后续可扩展 QQ 音乐、酷狗等
2. **依赖第三方 API 节点**：网易云搜索和链接获取依赖公共节点，节点可能失效
3. **B 站回退需浏览器**：试听回退需要浏览器已启动，否则会先启动浏览器
4. **歌词仅支持网易云**：其他平台暂无歌词接口
