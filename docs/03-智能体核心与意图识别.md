# 智能体核心与意图识别设计文档

> 快速正则 + ReAct 多步推理循环（思考→行动→观察→再思考）+ 工具结果回喂 + 长期记忆 + 异步记忆提取。

---

## 1. 设计目标

| 目标 | 说明 |
|------|------|
| 快速响应 | 常见单工具指令（打开/关闭/搜索）用正则秒判，不调 LLM |
| 多步推理 | 复杂/复合任务用 ReAct 循环，支持多工具串行调度 |
| 工具结果回喂 | 工具执行结果作为 observation 喂回 LLM，决定下一步 |
| 工具丰富 | 打开软件、关闭进程、网页搜索、搜索并打开 |
| 记忆增强 | 对话时检索相关长期记忆注入 ReAct 上下文 |
| 异步记忆 | 对话结束后异步提取记忆，不阻塞回复 |
| 流式输出 | 最终回复支持流式，配合 TTS 实时朗读 |
| 防死循环 | 最多 5 轮 ReAct 迭代，超时强制总结 |

## 2. Agent 类结构

```
modules/agent_core.py
└── class Agent
    ├── TOOL_DEFINITIONS                       # 工具注册表（自描述，供 LLM 选择）
    ├── MAX_REACT_ITERATIONS = 5               # ReAct 最大迭代轮数
    ├── COMPLEX_ACTION_PATTERN                 # 复杂动作指示词（路由到 ReAct）
    ├── __init__(llm, app_ctrl, searcher, memory)
    │
    ├── process(text, stream_callback)         # 主入口
    │   ├── _fast_intent(text)                 # 第一层：正则意图识别
    │   │   ├── OPEN_PATTERNS / CLOSE_PATTERNS
    │   │   └── SEARCH_BEST_PATTERNS / SEARCH_ONLY_PATTERNS
    │   ├── _is_complex_command(target, text)  # 检测多步/复合任务
    │   ├── [快速路径] _execute_single_tool()  # 简单单工具指令直接执行
    │   └── [ReAct 路径] _react_loop(text)     # 多步推理循环
    │       ├── retrieve_relevant_memories()   # 检索长期记忆
    │       ├── for i in MAX_REACT_ITERATIONS:
    │       │   ├── _ask_react_action()        # LLM 决定下一步（含观察历史）
    │       │   ├── [finish] → 输出最终回复
    │       │   └── [tool] → _execute_tool() → 加入 observations
    │       ├── _generate_final_streaming()    # 兜底：超时强制流式总结
    │       ├── _push_history()
    │       └── 异步写入记忆
    │
    ├── _execute_tool(tool, target)            # 统一工具执行（返回 observation）
    ├── _stream_emit(text, cb)                 # 模拟流式输出
    ├── _format_observations(observations)     # 格式化观察历史供 LLM 参考
    ├── _clean_target(s)                       # 清理目标词
    ├── _push_history(user, assistant)         # 维护对话历史
    └── _async_add_memory(conv_text, sid)      # 后台记忆提取
```

## 3. 路由：快速路径 vs ReAct 循环

### 3.1 第一层：快速正则（零延迟，单工具指令）

**目的**：常见指令直接执行，避免 LLM 调用开销。

```python
OPEN_PATTERNS = [
    # 在X盘打开XX文件夹
    re.compile(r"^(?:请?(?:帮我|帮|替我|替))?(?:在|去)([A-Za-z])盘(?:里)?(?:打开|启动|运行|点开|开启|进|进一下|看一下)\s*(?:一下|下)?(.+?)(?:文件夹|目录|文件)?\s*[。.！!？?]*$"),
    # 打开X盘YY
    re.compile(r"^(?:请?(?:帮我|帮|替我|替))?(?:打开|启动|运行|点开|开启|进|进一下|启动一下)\s*(?:一下|下)?([A-Za-z])盘(?:里)?[\\\\/]?(.+?)(?:文件夹|目录|文件)?\s*[。.！!？?]*$"),
    # 打开XX
    re.compile(r"^(?:请?(?:帮我|帮|替我|替))?(?:打开|启动|运行|点开|开启|进|进一下|启动一下)\s*(?:一下|下)?(.+?)(?:软件|程序|应用|文件)?\s*[。.！!？?]*$"),
    # 我想打开XX
    re.compile(r"^我想(?:打开|启动|运行|看一下|用)\s*(?:一下|下)?(.+?)(?:软件|程序|应用|文件)?\s*[。.！!？?]*$"),
    # XX给我打开
    re.compile(r"^(.+?)(?:给我|帮我)?(?:打开|启动|运行)\s*(?:一下|下)?\s*[。.！!？?]*$"),
]

CLOSE_PATTERNS = [
    re.compile(r"^(?:请?(?:帮我|帮|替我|替))?(?:关闭|关掉|关|退出|结束|停止)\s*(?:一下|下)?(.+?)(?:软件|程序|应用|进程)?\s*[。.！!？?]*$"),
    re.compile(r"^我想(?:关闭|关掉|关|退出|结束)\s*(?:一下|下)?(.+?)(?:软件|程序|应用|进程)?\s*[。.！!？?]*$"),
]

SEARCH_BEST_PATTERNS = [
    # 搜一下XX / 查一下XX / 百度一下XX
    re.compile(r"^(?:请?(?:帮我|帮|替我|替))?(?:打开|开|启动)?(?:浏览器|网页)?\s*(?:搜一下|搜搜|搜索|查一下|查一查|查|找一下|找找|百度一下|谷歌一下|bing一下)\s*(?:一下|下)?(.+?)(?:信息|内容|资料)?\s*[。.！!？?]*$"),
    # ...
]

SEARCH_ONLY_PATTERNS = [
    # 列出XX的搜索结果
    re.compile(r"^(?:请?(?:帮我|帮))?列出?(.+?)的?搜索结果\s*[。.！!？?]*$"),
    # 只搜XX不打开
    re.compile(r"^只(?:搜索|搜|查)(?:一下|下)?(.+?)(?:不用打开|不打开|不要打开)\s*[。.！!？?]*$"),
]
```

**匹配优先级**（避免误判）：
```
SEARCH_ONLY → SEARCH_BEST → CLOSE → OPEN → chat
```

**特殊处理**：
- "在 X 盘打开 YY" 解析为路径 `X:\YY`，直接交给 AppController 打开
- 排除代词（"我"、"自己"、"你"）作为目标

### 3.2 复杂指令检测（路由到 ReAct）

正则匹配后，检测是否为多步/复合任务。出现以下任一情况进入 ReAct 循环：

```python
COMPLEX_ACTION_PATTERN = re.compile(
    r"(然后|接着|再|之后|并|并且|同时|以及|"           # 序列连接词
    r"发|发送|写|编辑|分享|上传|下载|整理|分析|总结|告诉|提醒|通知|"  # 复杂动作
    r"查找|找出|筛选|排序|合并|对比|计算|翻译)"
)

def _is_complex_command(self, target: str, full_text: str) -> bool:
    # 整句中包含序列连接词（"打开微信然后发消息"）
    if self.COMPLEX_ACTION_PATTERN.search(full_text):
        return True
    # target 中残留其他动作动词（正则误捕获了多步指令）
    if target and self.COMPLEX_ACTION_PATTERN.search(target):
        return True
    return False
```

**示例**：
- "打开微信" → 快速路径（单工具）
- "打开微信然后发消息给妈妈" → ReAct（含"然后"）
- "搜一下Python教程" → 快速路径
- "搜一下Python教程然后打开第一个" → ReAct（含"然后"）
- "整理本周工作文档" → ReAct（含"整理"）

### 3.3 第二层：ReAct 多步推理循环

**目的**：处理需要多工具串行、根据中间结果决策的复合任务。

**协议**：每轮 LLM 输出一个 JSON，包含 thought / tool / target / answer 四个字段。

```python
TOOL_DEFINITIONS = [
    {"name": "open_app", "description": "打开软件/程序/文件", "params": {"target": "..."}},
    {"name": "close_app", "description": "关闭进程", "params": {"target": "..."}},
    {"name": "search_and_open", "description": "搜索并打开最佳结果", "params": {"target": "..."}},
    {"name": "search", "description": "只搜索不打开", "params": {"target": "..."}},
    {"name": "finish", "description": "任务完成，给出最终回复", "params": {"answer": "..."}},
]
```

**LLM 决策输出**：

```json
{
  "thought": "先搜索 Python 教程",
  "tool": "search",
  "target": "Python教程",
  "answer": ""
}
```

或终止时：

```json
{
  "thought": "已完成搜索和打开",
  "tool": "finish",
  "target": "",
  "answer": "已为你找到并打开 Python 教程官网。"
}
```

**JSON 提取容错**：

```python
m = re.search(r"\{[\s\S]*\}", raw)
if m:
    obj = json.loads(m.group(0))
```

LLM 输出即使有额外文字也能提取到 JSON。

## 4. 主流程：process()

```
用户输入 text
    ↓
_fast_intent(text)  ← 第一层正则
    ↓
┌──────────────────────────────────────────────────────────┐
│ intent ∈ {open_app, close_app, search, search_only}      │
│   ↓                                                       │
│ _is_complex_command(target, text)?                        │
│   ├── 否 → _execute_single_tool()  快速路径，绕过 LLM     │
│   └── 是 → _react_loop()           多步推理              │
└──────────────────────────────────────────────────────────┘
    ↓（intent=chat，纯聊天或复杂任务）
_react_loop(text)
    ↓
┌──────────────────────────────────────────────────────────┐
│ 1. retrieve_relevant_memories(text)  ← 检索长期记忆        │
│ 2. for i in range(MAX_REACT_ITERATIONS=5):                │
│ │   ├── _ask_react_action(text, observations, memory)     │
│ │   │   ← LLM 返回 {thought, tool, target, answer}        │
│ │   ├── if tool == finish:                                │
│ │   │   ├── answer 非空 → _stream_emit(answer) 模拟流式   │
│ │   │   └── answer 为空 → _generate_final_streaming()     │
│ │   │                       ↑ 单独触发流式 LLM 调用        │
│ │   │   └── break                                         │
│ │   └── else:                                             │
│ │       ├── _execute_tool(tool, target)                   │
│ │       │   ← 返回 (ok, observation, action_info)         │
│ │       └── observations.append({thought, tool,           │
│ │                                 target, observation})   │
│ │                                 ↑ 工具结果回喂 LLM      │
│ 3. [超出最大迭代] _generate_final_streaming() 强制总结     │
│ 4. _push_history(text, final_answer)                      │
│ 5. 异步线程写入记忆                                        │
└──────────────────────────────────────────────────────────┘
    ↓
返回 (final_answer, action_info)
```

### 4.1 动作详情 action_info

```python
# 不同动作返回不同的 action_info
{"action": "chat"}                                          # 纯聊天/ReAct 完成
{"action": "open_app", "target": "微信", "success": True}   # 打开软件
{"action": "close_app", "target": "PS", "success": True}    # 关闭软件
{"action": "search", "target": "Python", "results": [...]}  # 只搜索
{"action": "best_open", "target": "春节", "success": True,  # 搜索并打开
 "chosen": {"title": "...", "url": "..."}}
```

action_info 反映**最后一次工具调用**的状态。如果 ReAct 循环中调用了多个工具，只保留最后一个的 info。

UI 层可根据 `action` 类型显示不同提示。

## 5. ReAct 循环：工具执行 + 结果回喂

### 5.1 核心循环

```python
def _react_loop(self, text, stream_callback):
    observations = []  # 已执行步骤的历史
    action_info = {"action": "chat"}

    # 检索长期记忆（一次性，整轮复用）
    memory_context = ""
    if self.memory:
        relevant = self.memory.retrieve_relevant_memories(text)
        if relevant:
            memory_context = self.memory.build_context_text(relevant)

    for i in range(self.MAX_REACT_ITERATIONS):  # 最多 5 轮
        decision = self._ask_react_action(text, observations, memory_context)
        tool = decision.get("tool", "finish")
        answer = decision.get("answer", "")

        # 终止条件
        if tool in ("finish", "none", ""):
            if answer:
                final_answer = answer
                if stream_callback:
                    self._stream_emit(answer, stream_callback)  # 模拟流式
            else:
                final_answer = self._generate_final_streaming(...)  # 兜底流式
            break

        # 执行工具
        target = decision.get("target", "").strip()
        ok, obs, info = self._execute_tool(tool, target)
        action_info = info
        observations.append({                  # ★ 工具结果回喂
            "thought": decision.get("thought", ""),
            "tool": tool, "target": target,
            "observation": obs, "success": ok,
        })
    else:
        # 超过最大迭代，强制流式总结
        final_answer = self._generate_final_streaming(...)
```

### 5.2 统一工具执行

```python
def _execute_tool(self, tool, target) -> Tuple[bool, str, Dict]:
    """返回 (是否成功, 观察结果文本, 动作详情)。
    观察结果文本会被回喂给 LLM 用于下一步决策。"""
    if tool == "open_app":
        ok, msg = self.app_ctrl.open_app(target)
        return ok, f"打开「{target}」：{msg}", {"action": "open_app", ...}
    if tool == "search":
        results = self.searcher.search(target, num_results=5)
        lines = [f"搜索「{target}」返回 {len(results)} 条结果："]
        for i, r in enumerate(results[:5], 1):
            lines.append(f"{i}. {r.get('title','')} - {r.get('url','')}")
        return bool(results), "\n".join(lines), {"action": "search", ...}
    # ... 其他工具
```

### 5.3 观察历史格式化

每轮 LLM 决策时，把已执行的全部步骤格式化为文本作为上下文：

```python
def _format_observations(self, observations) -> str:
    lines = []
    for i, obs in enumerate(observations, 1):
        status = "成功" if obs.get("success") else "失败"
        lines.append(
            f"[步骤{i}] 思考: {obs.get('thought','')}\n"
            f"  动作: {obs.get('tool','')}({obs.get('target','')}) [{status}]\n"
            f"  观察: {obs.get('observation','')}"
        )
    return "\n".join(lines)
```

LLM 看到完整的"思考-行动-观察"链，能基于失败结果换策略、基于成功结果决定下一步。

### 5.4 流式输出策略

| 场景 | 流式方式 |
|------|----------|
| LLM 直接给出 finish + answer | `_stream_emit()` 按字符块模拟流式 |
| LLM 给出 finish 但 answer 为空 | `_generate_final_streaming()` 真流式 LLM 调用 |
| 超过最大迭代强制总结 | `_generate_final_streaming()` 真流式 LLM 调用 |

模拟流式避免重复调 LLM（答案已在 ReAct 决策中生成）；真流式用于兜底场景，需要单独生成回复。

## 6. 长期记忆集成

### 6.1 检索注入

ReAct 循环开始前检索相关记忆，整轮复用（避免每轮重复检索）：

```python
memory_context = ""
if self.memory:
    relevant = self.memory.retrieve_relevant_memories(text)
    if relevant:
        memory_context = self.memory.build_context_text(relevant)

# 记忆注入 ReAct 决策的 system prompt
if memory_context:
    sys_prompt += f"\n长期记忆（可参考，用于个性化回复）：\n{memory_context}\n"
```

记忆也会注入兜底流式生成的消息序列：

```python
def _build_final_messages(self, final_prompt, memory_context):
    msgs = [{"role": "system", "content": ai_persona}]
    if memory_context:
        msgs.append({"role": "system", "content": memory_context})
    msgs.extend(self._history)
    msgs.append({"role": "user", "content": final_prompt})
    return msgs
```

### 6.2 异步写入

对话结束后，后台线程提取记忆，不阻塞用户收到回复：

```python
# 异步写入记忆（不阻塞回复）
if self.memory:
    conv_text = f"用户：{text}\n助手：{final_answer}"
    t = threading.Thread(
        target=self._async_add_memory,
        args=(conv_text, self._session_id),
        daemon=True
    )
    t.start()

def _async_add_memory(self, conv_text, session_id):
    try:
        self.memory.add_memory(conv_text, session_id)
    except Exception:
        pass   # 记忆失败不影响主流程
```

## 7. 对话历史管理

```python
def _push_history(self, user: str, assistant: str):
    self._history.append({"role": "user", "content": user})
    self._history.append({"role": "assistant", "content": assistant})
    if len(self._history) > 20:
        self._history = self._history[-20:]   # 滑动窗口，保留最近 10 轮
```

**注意**：快速路径和 ReAct 路径都会 push 历史。session_id 基于线程 ID 生成，用于记忆来源追踪。ReAct 循环内部的中间步骤（thought/observation）不推入 `_history`，只保留最终回复。

## 8. 流式输出集成

```python
# main_window.py
def _send_message(self, text):
    stream = True
    self._worker = AgentWorker(self.agent, text, stream)
    self._worker.partial.connect(self._on_llm_partial)   # 增量
    self._worker.done.connect(self._on_llm_done)         # 完成
    self._worker.error.connect(self._on_llm_error)       # 错误
    self._worker.start()
    # 同时启动 TTS 流式朗读
    if self.tts and self.tts.auto_play:
        self.tts.speak_streaming_start()
```

`AgentWorker` 是 QThread，在子线程调用 `agent.process()`，通过信号把流式增量发回主线程。这样 LLM 阻塞调用不会卡死 UI。

## 10. 踩坑记录

| 问题 | 根因 | 解决 |
|------|------|------|
| "打开我自己" 误判 | 代词被当作目标 | 排除 "我/自己/你" |
| "在 D 盘打开工作" 解析失败 | 正则只支持单字母盘符 | 专门处理 `([A-Za-z])盘` 格式 |
| LLM 工具判断输出非 JSON | 模型有时加额外解释 | `re.search(r"\{[\s\S]*\}")` 提取 |
| 记忆写入阻塞回复 | 同步调用 LLM 提取记忆 | 改为 daemon 线程异步写入 |
| 工具结果直接返回太生硬 | 把日志甩给用户 | 工具结果作为 observation 回喂 LLM，由 LLM 生成自然语言回复 |
| "打开微信发消息给妈妈" 误判 | 正则贪婪匹配把"微信发消息给妈妈"当单工具 target | `_is_complex_command()` 检测复杂动作词，路由到 ReAct |
| 单步工具判断无法处理多步任务 | 旧架构只调一次 LLM 工具判断 | 引入 ReAct 循环，最多 5 轮思考-行动-观察 |
| 工具失败后无法换策略 | 旧架构工具结果不回喂 LLM | observations 全程记录，LLM 看到失败可换关键词或换工具 |
| ReAct 循环可能死循环 | LLM 反复调用同一失败工具 | MAX_REACT_ITERATIONS=5 强制上限 + prompt 提示"不要重复失败工具" |
| ReAct 决策的 answer 非流式 | LLM 一次性返回完整 JSON | `_stream_emit()` 按字符块模拟流式，保留 UI 体验 |
| ReAct 决策 answer 为空时无回复 | LLM 偶尔只返回 tool=finish 不带 answer | `_generate_final_streaming()` 兜底单独触发流式生成 |
