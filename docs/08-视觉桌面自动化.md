# 视觉桌面自动化模块设计文档

> 利用 VLM (Visual Language Model) 实现"所见即所得"的通用桌面自动化。通过截图 + 视觉理解 + 坐标映射，智能体能够执行那些难以用结构化指令描述的动态任务，显著提升处理不常见/未定义指令的能力。

---

## 1. 设计理念

**超越关键词匹配的局限**：传统的自动化依赖于窗口标题、进程名或预定义的坐标偏移。一旦界面更新或控件消失，指令就会失效。
**VLM 的优势**：通过将屏幕截图直接发送给多模态大模型，智能体获得了"视觉"能力。它可以像人类一样"看"屏幕，理解控件的语义（"发送"、"同意"、"那个蓝色的按钮"），从而处理任意未知的界面和非结构化指令。

**典型应用场景**：
- 处理弹窗："关掉那个烦人的广告弹窗"
- 动态操作："在聊天框里输入这句话并发送"
- 视觉定位："点击屏幕右上角的用户头像"
- 容错交互："先截屏看看现在是什么界面，然后再决定下一步"

## 2. DPI 处理（核心改进）

### 2.1 问题根源

Windows DPI 缩放（125%、150% 等）会导致**逻辑坐标**与**物理坐标**不一致：
- `GetSystemMetrics(0)` 返回物理像素（如 1920×1080）
- 但某些 API（如 `pyautogui`）在非 DPI 感知进程中使用逻辑坐标（如 1536×864）

如果截图和点击使用不同的坐标系，VLM 定位就会不准。

### 2.2 解决方案

1. **DPI 感知**：Qt（PyQt6）会自动设置 `PER_MONITOR_AWARE_V2`，使进程使用物理像素坐标
2. **DPI 检测**：`_detect_dpi_scale()` 方法检测实际 DPI 缩放因子
3. **统一坐标系**：所有操作（截图、VLM、点击）都使用物理像素坐标
4. **边界校验**：`find_element()` 返回前校验坐标是否在图片范围内
5. **实际尺寸**：`capture_screen()` 返回图片的实际像素尺寸（而不是请求的尺寸）

### 2.3 坐标校准工具

项目提供了 `calibrate_coordinates()` 方法用于诊断坐标映射问题：

```python
automator = VisionAutomator(llm_client)
result = automator.calibrate_coordinates()
# 返回: {"max_offset": 2, "details": "坐标精准..."}
```

该方法会：
- 在 5 个测试点移动鼠标
- 读取鼠标实际位置
- 计算目标坐标与实际坐标的偏移
- 输出诊断结果

## 4. 核心工作流程

### 4.1 通用执行链路

当智能体接收到一个无法用现有工具处理的"自由指令"时，启动视觉自动化流程：

```
用户: "帮我关掉那个弹窗"
    ↓
agent_core.py 判定为"视觉操作"意图
    ↓
VisionAutomator.find_element("关闭按钮")
    ├── capture_screen()      # 1. 截屏（返回实际图片尺寸）
    ├── 构造 Prompt（明确告知图片分辨率）
    ├── llm.vision_chat()     # 2. 调用 VLM 分析图像
    ├── 坐标边界校验          # 3. 确保坐标在图片范围内
    └── 返回定位结果
    ↓
click(x, y)                   # 4. 点击（带边界校验）
    ├── 边界检查（屏幕范围内）
    ├── _move_mouse_to(x, y)  #    SetCursorPos（物理坐标）
    ├── 位置验证（读取实际位置）
    └── mouse_event 点击
    ↓
返回执行结果给用户
```

### 4.2 VLM Prompt 设计

为提高 VLM 定位准确率，Prompt 中明确包含：
- **图片实际分辨率**：告诉 VLM 图片是多少像素
- **DPI 缩放因子**：让 VLM 理解坐标的物理意义
- **坐标范围**：明确要求坐标在 [0, width] × [0, height] 内

```python
prompt = f"""你是一个桌面自动化助手。请在这张屏幕截图中找到【{description}】。

图片实际分辨率：{width}x{height} 像素（DPI缩放={self._dpi_scale:.2f}）

要求：
1. 返回该元素中心点的屏幕坐标 (x, y)
2. 坐标范围：x ∈ [0, {width}], y ∈ [0, {height}]
...
```


### 5.2 多方法鼠标移动 (_move_mouse_to)

按可靠性排序：
1. **SetCursorPos**（最可靠，使用物理坐标）
2. **win32api.SetCursorPos**
3. **pyautogui.moveTo**（可能有偏移，仅作回退）

每个方法都验证鼠标是否移动到目标位置。

### 5.3 坐标边界校验

```python
def find_element(self, description, region=None):
    # ... VLM 返回坐标 ...
    x, y = int(x), int(y)
    
    # 关键：边界校验
    x = max(0, min(width - 1, x))
    y = max(0, min(height - 1, y))
    
    if region:
        x += region[0]  # 加上区域偏移
        y += region[1]
    
    return {"x": x, "y": y, ...}
```

## 7. 调试技巧

### 7.1 查看诊断信息

```python
automator = VisionAutomator(llm_client)
diag = automator.get_diagnostics()
# 返回:
# {
#   "dpi_scale": 1.25,
#   "screen_physical": "1920x1080",
#   "screenshot_size": "1920x1080",
#   "size_match": True,  # 关键：应该为 True
#   "image_saved": True,
# }
```

如果 `size_match` 为 `False`，说明截图尺寸与屏幕尺寸不一致，VLM 坐标会有偏移。

### 7.2 运行坐标校准

```python
result = automator.calibrate_coordinates()
# 查看 max_offset：
# - ≤ 5px: 精准
# - 5~20px: 基本可用
# - > 20px: 有问题，需要调整
```

### 7.3 查看保存的截图

截图会保存到 `temp/latest_screenshot.png`，可以用任何图片查看器打开检查。

### 7.4 查看日志

日志中会显示：
- `🖥️ VisionAutomator 初始化: DPI缩放=1.25`
- `📸 截图完成: 请求尺寸=1920x1080 实际尺寸=1920x1080`
- `VLM 定位结果: '按钮' → (500,300) 图片尺寸=1920x1080`
- `🖱️ 准备点击: (500,300) 次数=1 DPI=1.25`
- `✅ 点击完成: 目标(500,300) 实际(500,302) 偏差(0,2)`

## 8. 局限与未来

- **依赖网络/本地 VLM**：需要强大的多模态模型支持（如 GPT-4o, qwen-vl-max 等）。
- **响应速度**：截图 + VLM 推理比纯文本 LLM 慢，不适合高频循环任务。
- **规划能力**：当前仅支持单步操作（找 -> 点），未来可扩展为"看图规划"。
- **多显示器**：当前主要针对主显示器，多显示器支持需要进一步优化。
